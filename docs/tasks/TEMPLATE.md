# 当前任务模板

此模板用于 `docs/tasks/current.md` 中已承诺任务。Feature Spec 描述完整用户能力，Current Task 描述其中一个较小、可独立执行、验证和交接的工作单元。任务应默认拆细，避免把新增主要行为、完整回归、平台验收和文档收尾合并成一个大任务。

状态使用顺序必须为：`待开始 → 进行中 → 已完成`。开始任何实现代码、实现性测试或配置修改前，先在 `current.md` 将目标任务改为“进行中”，填写开始日期和当前进度，并确认没有其他进行中任务；不得在实现后补记。完成验证并记录真实结果后才能改为“已完成”，下一个任务开始时重新执行同一状态门禁。

```markdown
### 任务名称

- **状态**：待开始 | 进行中 | 已完成（开始实现前必须先改为“进行中”）
- **开始日期**：YYYY-MM-DD（待开始时省略）
- **Feature Spec**：`docs/features/example.md`
- **目标**：本任务独立交付的一个主要用户行为，或必要且可独立验证的底层契约。
- **范围**：本任务必须完成的行为和必要失败保护。
- **非范围**：留给后续任务或明确不在本功能内处理的内容。
- **依赖**：开始本任务前必须完成的任务、规格或系统能力。
- **拆分检查**：说明本任务为何已是合适颗粒度；若包含多个入口、多个失败分支、完整回归或平台验收，说明哪些内容被拆到前置或后续任务。
- **实施要点**：必要的实现顺序或边界；不写可直接从代码恢复的流水账。
- **完成标准**：可观察结果及本任务实际需要执行的自动化、构建或人工验证。
- **当前进度**：仅进行中任务填写，并在主要阶段完成、完整验证前、压缩前、实现路径变化或会话交接前更新；保持简短。
  - **已完成**：已经落盘且无需重复的结果。
  - **剩余**：仍属于本任务但尚未完成的内容。
  - **修改文件**：本次相关文件；需要时标明用户已有改动。
  - **已验证**：实际运行的定向验证及结果。
  - **下一动作**：恢复后唯一应先执行的动作。
- **验证记录**：完成时填写实际执行结果；未运行的检查不得写为通过。
- **交接信息**：仅记录下一会话无法轻易从代码与 Git 恢复的信息。
```

拆分判断：如果一个任务包含多个可分别演示的用户流程、多个独立破坏性选择，或其中一部分完成后已经可以单独验收，应继续拆分。标题或范围中出现“完整”“全部”“集成”“收尾”时，必须确认该任务是否仍包含大块未实现行为；若包含，应拆出前置实现任务。跨越前端、IPC、Rust 核心和测试不自动意味着任务过大；若这些修改共同交付同一个行为，应保持为一个垂直切片。
