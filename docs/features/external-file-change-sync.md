# 外部文件变更实时同步

> 状态：已完成；干净标签实时监听、自动刷新、脏标签主动冲突、实时缺失、实时重载失败保护、实时只读变化同步、聚焦恢复兜底、完整自动化、release 构建与 macOS 真实文件交互验收均已完成（2026-08-12）

## 背景与目标

Textora 已能在普通保存时发现关联文件被外部修改，并提供重新加载、强制覆盖和取消操作；文件缺失也能在应用重新聚焦时进入保留或关闭流程。但当文件由其他编辑器、格式化工具、脚本或同步程序改写时，Textora 不会主动展示最新内容，用户可能继续阅读旧版本，直到保存或重新聚焦后才发现问题。

本功能目标是在 Textora 运行期间持续观察每个已打开文件的磁盘状态：标签没有本地修改时，外部新版本经安全、完整读取后自动替换当前内容并及时展示；标签存在未保存修改或磁盘版本无法安全读取时，绝不静默覆盖编辑内容，而是复用现有冲突和缺失保护，提供明确、可重试的处理入口。

## 范围

- 持续观察所有已关联文件在磁盘上的内容修改、原子替换和路径缺失，不要求用户先保存、切换标签或重新聚焦应用。
- 外部事件只作为复核触发器；Rust 文档核心按后端可信路径重新观测并建立一致快照，确认实际字节指纹变化后才更新会话。
- 标签无本地修改时，自动读取并展示最新磁盘内容，同时更新编码、BOM、换行、字节数、指纹、只读状态和语言识别所依赖的描述信息。
- 标签有未保存修改时，不自动替换编辑内容；把已确认的磁盘内容变化交给现有内容冲突流程，由用户选择重新加载、强制覆盖或取消。
- 文件被删除或从原路径移走时，复用现有“在应用中保留或关闭”流程；首版不猜测或自动跟随移动后的新路径。
- 自动重载失败时保留当前内容，显示绑定对应标签的可理解错误，并允许重试；后续普通保存仍必须经过既有冲突保护。
- 支持多标签独立监听、后台标签状态更新、关闭/另存为后的监听迁移与清理，以及应用聚焦或从睡眠恢复后的兜底复核。

## 非范围

- 自动保存、双向实时协作、文本合并、三方 diff、冲突副本、备份、版本历史或崩溃恢复。
- 自动打开外部新建文件、目录树监听、项目工作区、最近文件或批量打开。
- 根据文件系统事件猜测文件移动后的新路径；重命名或移走按原路径缺失处理。
- 网络盘、云盘或所有文件系统上的严格即时性保证；监听通知可能被合并或丢失，因此仍保留聚焦/恢复复核。
- 超过 50 MiB 文件、GB18030 或新增编码；重新读取继续遵守现有文件大小与严格编码边界。
- 绕过只读、保存冲突、编码、换行、原子保存或未保存关闭保护。
- 向前端开放任意路径监听、宽泛文件系统、shell、网络权限，或让前端提交可信路径和文件指纹。

## 用户流程

### 无本地修改时自动刷新

1. 用户在 Textora 打开文件，标签处于已保存状态。
2. 其他应用改写或原子替换该文件。
3. Textora 收到变化信号，由 Rust 文档核心复核可信目标并读取一致快照。
4. 完整读取成功后，当前标签或后台标签自动采用磁盘新版本；若标签当前可见，编辑器立即展示最新内容。
5. 标签保持已保存状态，编码、换行、只读状态、语言与预览等派生界面基于新快照更新。

### 有本地修改时进入冲突处理

1. 用户在 Textora 中修改已打开文件但尚未保存。
2. 其他应用改写该文件。
3. Textora 确认磁盘指纹变化后保留本地编辑内容，并显示现有内容冲突界面。
4. 用户选择重新加载、强制覆盖或取消；各操作继续遵守既有破坏性确认、竞争复核和失败保护。

### 文件缺失或重载失败

1. 已打开文件被删除、重命名或移出原路径时，Textora 进入现有“保留或关闭”流程，不自动创建原文件或跟随新路径。
2. 若外部版本超限、编码无效、读取期间再次变化、权限不足或发生 I/O 错误，Textora 保留当前内容和关联，显示可重试错误；失败不得被误报为已同步。

## 行为规则与边界情况

- “实时”表示文件系统变化信号可在应用仍运行时主动触发处理，不依赖用户保存、切换标签或重新聚焦。为等待外部程序完成连续写入，允许对同一文档的短时事件做小范围防抖和合并；界面只展示完整一致快照，不展示部分写入状态。
- 文件系统通知不作为内容事实。每次处理都必须由 Rust 根据后端可信文档 ID 和可信路径重新检查当前目标；只有字节指纹或缺失状态确实变化时才产生用户可观察结果。仅修改时间、权限通知或重复事件而内容未变时不重置编辑器、选择、撤销历史或脏状态。
- 外部字节变化但解码后的文本相同仍视为新磁盘版本。无本地修改时更新编码/BOM、换行、字节数、指纹和只读信息；不得因文本相同而保留过期保存基线。
- 无本地修改的自动刷新必须以完整候选快照原子提交：后端可信描述和前端文本只有在元数据与二进制内容都成功取回后一起提升。读取失败、过期结果或标签已经关闭/另存时不得替换任何状态。
- 自动刷新属于外部版本采用，不产生本地编辑事务，不把标签标为 Modified，不把磁盘版本加入用户的 CodeMirror 撤销历史。刷新后光标和滚动位置尽量映射到新文档中的有效位置；无法保持原位置时收敛到最近有效位置，不因位置恢复失败拒绝内容更新。
- Markdown Preview、WYSIWYG、Mermaid 预览和语法高亮均以更新后的文本重新派生。自动刷新不得保存预览 DOM、WYSIWYG DOM 或其他派生产物。
- 标签存在本地修改时，任何外部内容变化都不得自动写入编辑器。冲突状态绑定对应文档 ID；后台标签可显示冲突状态，但破坏性选择只能作用于该标签，不能覆盖当前活动或其他标签。
- 主动检测到的内容冲突复用 `resolve-save-conflict.md` 的重新加载、强制覆盖和取消语义。取消表示保留本地编辑并退出当前提示，不表示接受磁盘版本；若磁盘仍与可信基线不同，后续新的实际变化或普通保存仍可再次触发冲突。
- 文件缺失复用现有保留/关闭语义。符号链接自身仍存在但真实目标缺失时同样视为缺失；目标被移到其他路径时首版不搜索、不自动打开新位置。
- 自动重载失败必须区分至少：目标再次变化、目标缺失、文件过大、编码不支持或无效、权限/只读状态读取失败及一般 I/O 错误。当前内容保持可见；错误提示属于发生变化的标签，切换标签不会把错误显示到其他文档。
- 保存、另存为和强制覆盖引起的本应用自身文件事件不得造成重复重载、伪冲突或编辑器闪回。后端以成功保存后的最终可信指纹消化对应事件；事件早于保存提交到达时，必须与正在进行的文档操作协调，待操作完成后再按最终可信状态复核。
- 常见编辑器采用临时文件加原子替换，可能产生 create/write/rename/remove 事件风暴。实现应按文档聚合事件并复核最终可信目标，不把中间瞬时缺失直接呈现为删除；只有稳定复核仍缺失时才进入缺失流程。
- 同一路径只允许关联一个标签的现有不变量保持不变。监听资源按后端文档 ID 管理：打开成功后建立，标签关闭或选择“保留”解除路径关联后释放，Save As 成功后从旧关联迁移到新关联；过期监听回调不得修改新会话。
- 后台标签也必须被观察和更新，不要求先切换为活动标签。自动刷新、冲突、缺失和错误结果分别绑定发起时的文档 ID；多标签同时变化时互不覆盖。
- 应用聚焦、从系统睡眠恢复或监听器报告溢出/失效时，对仍关联的文档执行兜底复核，以发现运行暂停期间遗漏的变化。兜底复核仍遵守事件路径相同的干净自动刷新、脏冲突和缺失保护。
- 只读属性变化但内容未变时更新只读状态，不替换文本或撤销历史；从只读变为可写不自动保存，从可写变为只读不丢弃本地修改。
- 内容继续通过二进制 IPC 传输。前端只接收稳定的文档 ID、变化类别和安全错误字段，不接收内部指纹、规范化真实路径、临时路径或 Rust 调试文本。
- 文件监听为 best-effort 提醒机制，不改变保存前指纹复核和原子替换的最终安全职责；即使监听遗漏，普通保存也不得覆盖未观测到的外部版本。

## 验收条件

- [x] 已保存的活动标签被其他应用改写后，无需保存、切换标签或重新聚焦即可自动展示完整最新内容，并保持未修改状态。
- [x] 已保存的后台标签被外部改写后独立更新；切换回来时显示新内容和正确的编码、换行、只读及语言状态，不污染其他标签。
- [x] 外部程序通过直接写入或临时文件原子替换更新目标时均能收敛到最终版本；短时事件风暴不会显示部分内容、重复刷新或误报缺失。
- [x] 外部字节版本变化但解码文本相同时，可信指纹和编码/BOM、换行等描述信息仍更新，编辑器内容、选择、撤销历史和脏状态不被无意义重置。
- [x] 标签有本地修改时，外部变化不覆盖编辑器，进入绑定正确标签的重新加载、强制覆盖或取消流程；三种选择与既有冲突规格一致。
- [x] 文件被删除、重命名或移走时进入现有保留/关闭流程；不会自动创建原路径、猜测新路径或关闭错误标签。
- [x] 自动重载遇到再次变化、超限、无效编码、权限或 I/O 错误时保留当前内容，显示对应标签的可重试错误，不更新可信基线或误报同步成功。
- [x] Textora 自身普通保存、另存为和强制覆盖产生的事件不会触发伪冲突、重复重载或内容闪回；保存后的可信指纹保持正确。
- [x] 打开、关闭、Save As、保留缺失文件、多标签并发及过期异步结果正确建立、迁移和释放监听，不泄漏监听资源或跨文档应用结果。
- [x] 应用聚焦、睡眠恢复或监听失效后的兜底复核能发现遗漏变化，并走与实时事件一致的自动刷新、冲突或缺失路径。
- [x] 自动刷新后 Markdown/代码/Mermaid 派生界面基于新源码更新；保存仍只写当前文本源码，不包含派生 DOM。
- [x] 监听实现不向前端开放任意路径、文件系统、shell 或网络权限；内容继续通过二进制 IPC，错误不泄露内部路径或指纹。
- [x] 自动化测试覆盖变化分类、一致重读、事件合并、自身保存抑制、干净/脏标签、删除/替换、失败保护、监听生命周期、多标签与过期结果；macOS release 真实文件交互验收通过。

3. **接入干净标签的实时监听与自动刷新**：建立监听生命周期和事件合并，打通受限 IPC 与 React 会话；无本地修改时自动采用新快照，并处理自身保存事件、后台标签和过期结果。此切片不新增脏标签冲突选择或缺失失败 UI。
4. **接入脏标签冲突与缺失/重载失败保护**：主动变化复用现有冲突与缺失流程，补充可重试错误、删除/移动、只读变化、聚焦/恢复兜底和多标签归属。
5. **外部文件变更实时同步集成验收与文档收尾**：运行完整自动化、release 构建和 macOS 真实文件交互验收，验证直接写入、原子替换、自身保存、编码/换行、多标签与失败保护；只做必要小修和文档收尾。
