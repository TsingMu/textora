# 多标签会话

> 状态：草案

## 背景与目标

Textora 当前已具备单文档的新建、打开、保存、另存为、冲突解决和未保存关闭保护。下一阶段需要把单文档工作台扩展为单窗口多标签会话，让用户可以同时打开或新建多个文本，快速切换处理，而不为普通编辑、文件安全和关闭保护引入新的丢失风险。

本功能目标是交付单窗口多标签阶段的完整会话基础：每个标签独立维护内容、文件关联、编码/换行、脏状态、保存状态、冲突/缺失提示和关闭保护；活动标签切换应快速、可理解，且不会让一个标签的异步文件操作污染另一个标签。

## 范围

- 在单个主窗口中创建、显示、切换和关闭多个标签。
- 支持新建空白标签。
- 支持把打开的本地文件加入新标签，读取失败不影响当前标签。
- 每个标签独立维护内容、显示名、路径、编码、换行、只读、脏状态、保存状态和错误状态。
- Save、Save As、文件缺失、保存冲突、窗口关闭与应用退出保护都作用于正确标签。
- 关闭单个标签时复用未保存关闭保护，允许保存、不保存或取消。
- 关闭窗口或退出应用时协调所有未保存标签，不能绕过任一标签的未保存保护。
- 后端可信文档状态能同时保存多个已打开文档的关联与冲突状态。

## 非范围

- 多窗口会话。
- 标签拖拽排序、拆分窗口、分组、固定标签或最近关闭标签恢复。
- 启动时恢复上次会话。
- 项目目录浏览、文件树、批量打开文件夹。
- 多标签之间的比较、同步滚动或合并。
- 自动保存、备份、崩溃恢复或版本历史。
- 列块编辑、Markdown 预览、Mermaid 或代码语法高亮的新增能力。

## 用户流程

1. 用户启动应用，默认看到一个 Untitled 标签。
2. 用户可以新建标签，得到另一个独立 Untitled 文档。
3. 用户打开本地文件时，成功后新建一个文件标签并切换到该标签；取消或失败时当前标签不变。
4. 用户在标签栏切换活动标签，编辑器、状态栏、保存按钮和错误提示随活动标签切换。
5. 用户关闭标签：
   - 未修改标签直接关闭。
   - 已修改标签显示保存/不保存/取消确认。
   - 取消后标签和内容保持不变。
6. 用户关闭窗口或退出应用时，应用检查所有未保存标签，并在用户逐一作出明确选择前保持运行。

## 行为规则与边界情况

- 每个标签必须拥有稳定的前端标签 ID；后端文档 ID 只表示可信文件关联，Untitled 或尚未保存标签可以没有后端关联。
- 活动标签是编辑器展示和命令默认作用对象；异步命令提交结果时必须复核标签 ID 和后端文档 ID，过期结果不得覆盖已经切换、关闭或重新打开的标签。
- 打开文件成功应创建新标签，不替换当前标签；若未来需要“在当前标签打开”，应另行规格化。
- 最后一个标签被关闭后应创建新的空白 Untitled 标签，避免窗口中没有可编辑文档。
- 标签显示名应能区分多个 Untitled 和多个同名文件；具体命名规则可在实现任务中选择，但不能影响保存目标。
- 单个标签处于保存、另存为、冲突解决或文件缺失处理时，该标签的相关操作应互斥；其他标签是否允许继续编辑或切换由首批实现任务明确，不能在实现中临时扩大范围。
- 关闭窗口或退出应用时若存在多个未保存标签，必须避免一次确认隐式放弃多个标签。首版可以逐个确认，也可以显示汇总确认，但必须明确每个将被保存或放弃的标签。
- 内容冲突或目标缺失只属于对应标签；处理完成后不得自动关闭其他标签或退出应用。
- 前端 capability 不新增宽泛文件系统、shell、网络或任意窗口控制权限。

## 验收条件

- [ ] 启动后至少有一个 Untitled 标签，用户可以新建多个 Untitled 标签并切换编辑，内容与脏状态互不影响。
- [ ] 打开文件成功会创建并切换到新标签；取消或失败不会替换当前标签内容和状态。
- [ ] Save、Save As、保存错误、冲突和文件缺失提示只影响发起操作的标签。
- [ ] 异步打开、保存、另存为或冲突解决返回过期结果时，不会覆盖当前活动标签或已关闭标签。
- [ ] 关闭未修改标签直接移除；关闭已修改标签显示明确保存/不保存/取消确认。
- [ ] 关闭最后一个标签后回到新的空白 Untitled 标签。
- [ ] 窗口关闭和应用退出会保护所有未保存标签，不会只检查当前活动标签。
- [ ] 重复关闭标签、关闭窗口或退出应用不会叠加提示、排队重复关闭或绕过已有确认。
- [ ] 后端可同时维护多个可信文档状态，保存/冲突/关闭命令不能误作用于其他标签。
- [ ] 自动化测试覆盖多标签创建、切换、打开成功/取消/失败、保存成功/失败、过期结果、单标签关闭和窗口/应用退出保护。
- [ ] macOS 13+ 构建、启动和真实交互验收通过，且权限仍保持最小。

## 依赖与约束

- 依赖已完成的打开、普通保存、首次保存、另存为、保存冲突解决和未保存关闭保护。
- 遵守 `docs/ARCHITECTURE.md` 的文本权威源、后端可信状态、二进制 IPC、失败保护和最小权限不变量。
- 遵守 D-007 的 macOS 个人文本工作台定位；多标签是单窗口能力，不恢复 Windows 平台验收范围。
- 现有 `DocumentStore` 目前按单活动文档设计，进入实现前需要先规划多文档可信状态模型。

## 开放问题

- 多个未保存标签在关闭窗口或退出应用时采用逐个确认，还是一个汇总确认界面？
- 首批多标签实现是否允许一个标签保存/打开时切换到其他标签继续编辑？
- 同一路径文件被打开多次时，是允许多个标签独立编辑，还是复用已有标签？
- Untitled 与同名文件标签的显示名如何去重？
- 标签关闭后是否保留撤销历史或最近关闭记录？首版倾向不保留。
