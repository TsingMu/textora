# 多标签会话

> 状态：已完成（2026-08-07）

## 背景与目标

Textora 当前已具备单文档的新建、打开、保存、另存为、冲突解决和未保存关闭保护。下一阶段需要把单文档工作台扩展为单窗口多标签会话，让用户可以同时打开或新建多个文本，快速切换处理，而不为普通编辑、文件安全和关闭保护引入新的丢失风险。

本功能目标是交付单窗口多标签阶段的完整会话基础：每个标签独立维护内容、文件关联、编码/换行、脏状态、保存状态、冲突/缺失提示和关闭保护；活动标签切换应快速、可理解，且不会让一个标签的异步文件操作污染另一个标签。

## 范围

- 在单个主窗口中创建、显示、切换和关闭多个标签。
- 支持新建空白标签。
- 支持把打开的本地文件加入新标签，读取失败不影响当前标签。
- 每个标签独立维护内容、显示名、路径、编码、换行、只读、脏状态、保存状态和错误状态。
- Save、Save As、文件缺失、保存冲突、窗口关闭与应用退出保护都作用于正确标签。
- 关闭单个标签时复用未保存关闭保护，允许保存、不保存或取消。
- 关闭窗口或退出应用时**逐一**协调所有未保存标签，不能绕过任一标签的未保存保护。
- 同一路径的文件再次打开时切换到已有标签，不新建重复标签。
- 后端可信文档状态能同时保存多个已打开文档的关联与冲突状态。

## 非范围

- 多窗口会话。
- 标签拖拽排序、拆分窗口、分组、固定标签或最近关闭标签恢复。
- 标签关闭后保留撤销/重做历史。
- 启动时恢复上次会话。
- 项目目录浏览、文件树、批量打开文件夹。
- 多标签之间的比较、同步滚动或合并。
- 自动保存、备份、崩溃恢复或版本历史。
- 列块编辑、Markdown 预览、Mermaid 或代码语法高亮的新增能力。

## 用户流程

1. 用户启动应用，默认看到一个 Untitled 标签。
2. 用户可以新建标签，得到另一个独立 Untitled 文档。
3. 用户打开本地文件时，若该路径尚未在任何标签打开，成功后新建一个文件标签并切换到该标签；若已在某标签打开，则直接切换到该标签且不重新读取磁盘；取消或失败时当前标签不变。
4. 用户在标签栏切换活动标签，编辑器、状态栏、保存按钮和错误提示随活动标签切换。一个标签正在后台普通保存，或系统文件面板已经关闭且文件仍在异步读取时，用户可切换到其他标签继续编辑；系统文件/目录选择面板、另存为面板、冲突解决、文件缺失或关闭确认等模态打开时，标签切换被锁定直到该模态关闭。
5. 用户关闭标签：
   - 未修改标签直接关闭。
   - 已修改标签显示保存/不保存/取消确认。
   - 取消后标签和内容保持不变。
6. 用户关闭窗口或退出应用时，应用按固定顺序逐一检查每个未保存标签，在每个标签的保存/不保存/取消选择完成前保持运行；任一标签选择取消即中止整个关闭/退出，已选择保存或不保存的标签按其选择生效，剩余标签保持不变。

## 行为规则与边界情况

- 每个标签必须拥有稳定的前端标签 ID；后端文档 ID 只表示可信文件关联，Untitled 或尚未保存标签可以没有后端关联。
- 活动标签是编辑器展示和命令默认作用对象；异步命令提交结果时必须复核标签 ID 和后端文档 ID，过期结果不得覆盖已经切换、关闭或重新打开的标签。
- 打开文件成功应创建新标签，不替换当前标签；若未来需要“在当前标签打开”，应另行规格化。
- 同一路径文件被再次打开时，按文件路径身份匹配已有标签：先比较规范化绝对选择路径；目标存在且可解析时再比较规范化真实路径，使原路径与符号链接别名归为同一文件。若某标签已打开该路径，切换到该标签且不重新读取磁盘，该标签已有的未保存编辑与冲突/缺失状态保持不变，后端也不为该次选择保留第二个文档；否则新建标签。
- 若一个标签 Save As 的目标路径已经关联到另一个打开标签，必须在覆盖确认和写盘前拒绝本次保存，保留两个标签的内容与状态，并提示该文件已在其他标签打开；不得通过覆盖、合并或静默切换产生两个关联同一路径的后端文档。目标身份使用与再次打开相同的规范化选择路径/真实路径规则；当前标签自身的原路径不属于此冲突，仍按普通保存路径处理。
- 最后一个标签被关闭后应创建新的空白 Untitled 标签，避免窗口中没有可编辑文档。
- 多个 Untitled 标签以数字后缀区分（如 `Untitled`、`Untitled 2`）；多个同名文件标签必要时附加区分信息。显示名只用于展示，绝不影响保存目标或后端关联（保存目标仍由后端可信路径与授权决定）。
- 单个标签处于保存、另存为、冲突解决或文件缺失处理时，该标签的相关操作互斥。后台普通保存以及系统文件面板关闭后的异步读取不锁定切换；系统文件/目录选择面板、另存为面板、冲突解决、文件缺失或关闭确认等模态一旦打开即锁定标签切换，直到该模态被关闭或解决，避免模态结果归属到错误标签。
- 关闭窗口或退出应用时若存在多个未保存标签，首版逐一为每个未保存标签复用现有保存/不保存/取消确认：任一标签选择取消即中止整个关闭/退出并保持运行；全部选择保存或不保存后才继续关闭窗口或退出应用。不会出现一次确认隐式放弃多个标签的情况。
- 内容冲突或目标缺失只属于对应标签；处理完成后不得自动关闭其他标签或退出应用。
- 前端 capability 不新增宽泛文件系统、shell、网络或任意窗口控制权限。

- [x] 打开文件成功会创建并切换到新标签；取消或失败不会替换当前标签内容和状态；同一文件再次打开会切换到已有标签且不重新读取。
- [x] 一个标签后台普通保存或系统文件面板关闭后仍在异步读取时，用户可切换到其他标签继续编辑；系统文件/目录选择、另存为、冲突、缺失或关闭确认等模态打开时标签切换被锁定。

- [x] 重复关闭标签、关闭窗口或退出应用不会叠加提示、排队重复关闭或绕过已有确认。

## 决议记录

- 2026-08-04 确认首版范围，原开放问题决议如下：
  1. 关闭窗口/退出应用的多未保存标签：**逐一**复用现有保存/不保存/取消确认，任一取消即中止；不建汇总面板。
  2. 跨标签并发：后台普通保存及系统文件面板关闭后的异步读取期间**允许**编辑与切换其他标签；系统文件/目录选择、另存为、冲突、缺失/关闭确认等模态打开时锁定切换。
  3. 同一路径身份：再次打开时**切换到已有标签**，不新建重复标签、不重新读取磁盘；Save As 命中其他标签已关联路径时在写盘前安全拒绝。匹配同时考虑规范化绝对选择路径与可解析的规范化真实路径，避免符号链接别名产生重复标签。
  4. Untitled 与同名文件去重：Untitled 用数字后缀；显示名只用于展示，不影响保存目标或后端关联。
  5. 标签关闭后不保留撤销/重做历史或最近关闭记录。

## 实现拆分

多标签按以下顺序拆成可连续交付的小切片，实现时优先保留现有单文档行为作为每个标签的垂直切片，不按技术层机械重写。`docs/tasks/current.md` 同一时间只保留下一个待执行切片。

1. **后端多文档可信状态（基础切片，不改前端）**：把 `DocumentStore` 由单活动文档重构为按文档 id 并发持有多个可信文档，每个文档独立维护可信元数据、待解决冲突（含内部版本与覆盖租约）、待取回内容/重载候选与保存目录授权；单文档退化为当前行为，既有自动化测试保持通过。本切片不接入前端，仅为后续多标签解除单活动文档约束。
2. **前端多标签会话与切换**：前端由单 `DocumentSession` 改为标签数组 + 活动标签 id；支持新建 Untitled 标签、切换、编辑隔离、Untitled 数字后缀去重与单标签关闭保护（复用现有保存/不保存/取消）。
3. **打开与保存按活动标签绑定**：打开文件新建并切换到新标签，候选内容按文档 id 提升到正确标签；普通保存、另存为、冲突解决与文件缺失均作用于发起标签，过期结果不覆盖其他标签；同一路径再次打开时切换到已有标签、不重复新建或读取，Save As 命中其他标签已关联路径时在覆盖确认和写盘前安全拒绝；路径身份覆盖规范化选择路径与符号链接真实路径。
4. **多标签关闭协调**：单标签关闭、窗口关闭与应用退出逐一协调所有未保存标签（决议 1），重复事件不叠加提示；模态期间锁定切换（决议 2）。
5. **集成验收**：完整回归、macOS 真实交互验收，规格状态改为已完成，README 同步。
