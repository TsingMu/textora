# 未保存关闭保护

> 状态：已确认

## 背景与目标

Textora 已能安全地打开、保存、另存为并解决外部修改冲突，但关闭主窗口或正常退出应用时尚未协调当前文档的未保存状态。用户可能通过窗口关闭按钮、快捷键、应用菜单或 Dock 退出应用；任何正常关闭入口都不能绕过文件安全规则并静默丢失编辑内容。

本功能交付单窗口阶段的完整关闭保护：未修改文档可以直接关闭；文档有未保存修改时，用户可以保存后关闭、明确放弃后关闭或取消关闭。保存取消、失败或进入冲突处理时必须保留窗口、内容和未保存状态，不得延迟执行一个用户已经无法看见的关闭意图。

## 范围

- 拦截 macOS 主窗口的正常关闭请求，包括窗口红色关闭按钮与 `⌘W`。
- 拦截应用的正常退出请求，包括 `⌘Q`、应用菜单 Quit 与 Dock Quit。
- 未修改文档直接允许原关闭或退出请求完成。
- 有未保存修改时显示应用内确认界面，提供“保存”“不保存”和“取消”三个明确操作。
- “保存”按当前文档状态复用普通保存、首次保存或另存为能力；完整成功后继续本次关闭或退出。
- “不保存”明确放弃当前内存修改并继续本次关闭或退出。
- “取消”、Escape、关闭确认界面或无法取得明确选择时取消本次关闭或退出并返回编辑。
- 关闭确认、保存流程、保存冲突、文件缺失提示和其他文件操作保持互斥，不出现重叠提示或重复关闭。

## 非范围

- 多标签或多窗口的逐文档关闭协调；本功能只处理当前单窗口、单文档会话。
- 自动保存、定时备份、崩溃恢复、版本历史或恢复用户已经明确选择“不保存”的内容。
- 进程崩溃、强制结束、`kill -9`、断电或操作系统无法给予应用交互机会的强制终止。
- 修改现有编码、换行、大小限制、只读、冲突检测、原子保存或文件缺失处理规则。
- 为关闭流程新增独立文件格式选择逻辑；首次保存与另存为继续复用现有格式选择和系统保存对话框。

## 用户流程

1. 用户通过窗口按钮、快捷键、应用菜单或 Dock 发起正常关闭/退出。
2. 若当前文档没有未保存修改，应用直接完成请求。
3. 若当前文档有未保存修改，应用阻止本次请求并展示关闭确认，说明文档名称和各操作后果。
4. 用户选择：
   - **保存**：保存当前完整编辑快照；保存成功后完成原关闭/退出。
   - **不保存**：明确放弃未保存修改并完成原关闭/退出。
   - **取消**：不读写磁盘并返回编辑。
5. 保存对话框被取消、保存失败、发生内容冲突或发现关联文件缺失时，应用取消本次关闭/退出并保留窗口；用户处理现有提示后需要重新发起关闭。

## 行为规则与边界情况

- 关闭判断以当前 React 文档会话的 `isDirty` 为准；窗口标题、按钮状态或后端文件指纹不能替代未保存状态。
- 未修改文档的正常关闭不得额外弹出确认，也不得因为没有后端文档 ID 的空白 Untitled 而受阻。
- 关闭确认必须明确显示当前文档名称；“不保存”是破坏性操作，不能获得默认焦点，也不能由 Escape、关闭提示或失焦隐式触发。
- Escape、关闭确认界面和系统级取消均等价于“取消”。取消不得改变内容、文档关联、编码、换行、指纹、未保存状态或磁盘文件。
- 用户选择“保存”后，编辑器和文件操作保持锁定，直至保存成功、取消或失败；提交保存的内容必须是用户确认关闭时看到的完整快照。
- 有路径、可普通保存的文档复用普通保存；Untitled 复用首次保存；关联目标只读而不能普通保存时复用另存为。格式选择或系统保存对话框取消等价于取消本次关闭。
- 普通保存继续保持原编码与单一换行风格；Mixed、不可编码、编码歧义、只读变化、超限、权限或一般 I/O 失败均不得关闭窗口或清除未保存状态。
- 保存触发内容变化冲突或目标缺失时，本次关闭意图立即失效，进入既有冲突或文件缺失处理流程；即使随后重新加载、覆盖、保留或放弃成功，也不得自动关闭，用户必须重新发起关闭。
- 保存成功后必须先提交新的可信描述信息并清除未保存状态，才能执行一次关闭授权；授权只对应产生它的当前窗口、当前文档与本次请求，不能被后续请求或新会话复用。
- “不保存”只允许一次当前正常关闭/退出通过，不得写盘、调用保存、改变磁盘文件或留下可使后续新窗口误判为已保存的会话状态。
- 关闭确认待处理期间的重复窗口关闭或退出请求只维持同一个提示，不重复排队、不切换默认选择，也不在用户作出选择后执行多次关闭。
- 打开、保存、另存为、格式选择、冲突解决或文件缺失提示正在进行时收到关闭/退出请求，应用必须安全阻止且不叠加第二个提示；当前操作结束后用户重新发起关闭。
- 正常退出可能同时产生应用退出与窗口关闭事件。两类事件必须归并为一个关闭决策，不能连续显示两次提示或在取消其中一个后由另一个事件绕过。
- 关闭授权与确认状态只保存在当前进程内，不写入用户文件或持久化偏好。
- 前端 capability 不新增宽泛文件系统、shell、网络或任意窗口控制权限；需要的窗口生命周期能力保持最小范围。

## 验收条件

- [ ] 未修改的空白 Untitled 和已打开文档通过窗口关闭按钮或 `⌘W` 时直接关闭，不显示多余确认。
- [ ] 已修改文档通过窗口关闭按钮或 `⌘W` 时只显示一个包含文档名称的保存/不保存/取消确认，窗口在明确选择前保持打开。
- [ ] 选择取消、按 Escape 或关闭确认界面时，内容、未保存状态、文档关联和磁盘文件均保持不变。
- [ ] 选择不保存时不写盘并完成关闭；该操作不能由默认焦点、Escape、失焦或重复关闭请求隐式触发。
- [ ] 已打开的可写文档选择保存时复用普通保存，成功提交可信状态后关闭；Untitled 选择保存时完成格式选择与首次保存后关闭。
- [ ] 只读关联文档选择保存时可通过另存为保留内容；格式选择或系统保存对话框取消时窗口保持打开且内容不变。
- [ ] Mixed、不可编码、编码歧义、超限、只读变化、权限或一般保存失败时不关闭、不清除未保存状态，并保留既有可理解错误。
- [ ] 保存发现内容冲突或目标缺失时进入既有解决流程且取消关闭意图；解决完成后不会自动关闭。
- [ ] `⌘Q`、应用菜单 Quit 与 Dock Quit 对未保存文档执行相同保护；取消后应用和窗口继续可用，保存或明确不保存后正常退出。
- [ ] 重复窗口关闭/退出以及退出同时产生的窗口事件只形成一个决策；忙碌或已有提示时不叠加关闭确认或排队稍后关闭。
- [ ] 自动化测试覆盖关闭决策状态机、普通保存/首次保存/另存为成功、取消、失败、冲突、文件缺失、过期授权、重复事件和窗口/应用退出归并。
- [ ] macOS 13+ 自动化、构建、启动及真实交互验收通过，且前端未获得宽泛文件系统、shell、网络或窗口权限。
