# 另存为目标路径与文件名选择

> 状态：已完成（2026-08-04）。本规格记录系统保存面板方案的目标选择能力；后续新体验「文件名与保存位置直接出现在应用内对话框」另见 `docs/features/save-as-inline-target-panel.md`。

## 背景与目标

Textora 已支持首次保存和另存为，但当前体验尚未把“用户可以清楚地修改目标目录与文件名”作为独立能力规格化。尤其是 Untitled 首次保存、已有文档另存为、只读文档另存为等流程，应在进入安全保存前给用户一个可理解、可修改的目标路径与名称选择体验。

本功能目标是在不放宽文件安全边界的前提下，改善首次保存/另存为的目标选择：系统保存面板应提供合理的默认文件名，并在可可靠实现时提供默认目录；用户可以在原生面板中改为指定路径和名字；取消或失败时不改变文档关联、内容和未保存状态。

## 范围

- 为 Untitled 首次保存提供合理的默认文件名。
- 为已有文档 Save As 提供当前文件名作为默认文件名；默认目录尽量定位到当前文件所在目录，但不得以破坏系统保存面板可用性为代价。
- 允许用户通过系统保存面板修改目标目录与文件名。
- 保存成功后当前会话显示用户实际选择的文件名与路径，并让后续普通保存写入该目标。
- 取消目标选择时保留当前内容、原路径、显示名和未保存状态。
- 保持已有安全保存、冲突检测、只读、编码、换行、大小限制和二进制 IPC 规则。

## 非范围

- 前端直接输入或提交任意目标路径。
- 自定义文件浏览器、最近目录列表、目录收藏、批量保存或批量重命名。
- 修改系统保存面板的覆盖确认语义。
- 自动追加或强制修改文件扩展名。
- 多标签下的批量另存为；多标签只复用本功能形成的单标签目标选择语义。

## 用户流程

1. 用户在 Untitled 文档选择 Save，或在已有文档选择 Save As。
2. 应用先展示已有格式选择界面，用户确认编码与换行。
3. 系统保存面板打开，并显示合理的默认文件名和目录。
4. 用户可以修改文件名、切换目录、确认保存，或取消。
5. 确认后后端按用户实际选择的目标执行现有安全保存流程；成功后标签和状态栏显示新目标。
6. 取消或失败时回到编辑状态，不改变原会话。

## 行为规则与边界情况

- 目标路径仍只能由 Rust 侧系统保存面板返回，前端不得提交路径字符串。
- Untitled 默认文件名应稳定、可理解，且不影响用户在系统面板中修改名称。
- 已有文档 Save As 默认目录优先使用当前文件所在目录；若目录不可用、无法转换为系统路径，或当前 Tauri/rfd/macOS 插件栈无法同时可靠设置默认目录与文件名，应退回系统默认目录，不阻断保存。
- 已有文档 Save As 默认文件名优先使用当前显示名；保存成功后显示名以实际目标为准。
- 用户选择当前原路径时，仍必须走普通保存同等的指纹、只读和冲突保护，不得借目标选择绕过外部修改检测。
- 系统保存面板取消不得清除关闭意图之外的会话状态；若该流程由关闭/退出保护触发，取消应保持窗口或应用运行。
- 不因本功能新增宽泛文件系统、shell、网络、dialog 或窗口控制权限；系统面板继续由受限 Rust 命令发起。

## 已确认结论（2026-07-31）

- **Untitled 默认文件名**：采用 `Untitled`（无扩展名），与会话显示名一致。理由：本规格非范围明确「不自动追加或强制修改文件扩展名」；提供无扩展名的 `Untitled` 作为可在系统面板修改的默认值最一致，用户若需扩展名可自行输入。Rust 侧以常量提供默认名，不要求前端传名，保持「目标只由 Rust 决定」。不采用 `Untitled.txt`（与「不自动追加扩展名」冲突）；不采用「跟随标签显示名」（当前单标签显示名即硬编码 `Untitled`，且 Rust 无标签概念，多标签属后续范围）。
- **是否记住上次保存目录**：首版**不**持久化，也**不**在会话内记忆「上次保存目录」。理由：工程无偏好持久化机制，新增会引入新的状态面与维护成本，违背最小范围。已有文档默认目录仅在当前 Tauri/rfd/macOS 插件栈可同时可靠设置默认目录与文件名时，才由当前文档父目录派生；否则退回系统默认目录，不阻断用户在系统保存面板中手动切换目录。Untitled 无路径时退回系统默认目录。最近目录列表/收藏属非范围。

## 实现前调查结论（2026-07-31）

**1. 系统保存对话框默认值能力（`tauri-plugin-dialog`，已在 `save-as-and-first-save.md` 2026-07-22 调查确认）**

- `app.dialog().file()` 链式 `set_file_name` / `set_directory` / `add_filter` / `set_title` 后 `blocking_save_file() -> Option<FilePath>`；`set_directory` 接受 `AsRef<Path>`。
- 覆盖确认由 OS 原生处理，返回值只给路径、不告知目标是否已存在（与本功能无关，沿用既有结论）。
- 修正结论：提供默认文件名**无需新依赖、无需新权限**；系统面板继续由 Rust 经 `app.dialog()` 发起，前端不经 dialog 权限，capability 不变。默认目录在 API 层可调用，但当前 `rfd` macOS 保存面板同时提供目录与文件名时存在渲染异常，不能作为本轮可靠完成项。

**2. 现状与缺口**

- `save_document_as`（`ipc.rs`）当前对话框构造只在有可信文档（已有文档另存为）时 `set_file_name(&trusted.display_name)`；**Untitled 首次保存不设默认文件名**，**已有文档另存为不设默认目录**。
- `TrustedDocument` 含 `path: PathBuf` 与 `display_name: String`，故 `trusted.path.parent()` 可取得当前文件所在目录作为默认目录。
- 前端 `createNewDocument` 的 `displayName: "Untitled"`；前端只提交格式选择与内容、不提交路径或名称，故默认值须由 Rust 侧决定（符合「目标路径只由 Rust 取得」）。

**3. 已被现有实现满足、无需新代码的验收点**

- 取消语义：`blocking_save_file()` 返回 `None` → 命令返回 `Ok(None)` → 前端恢复原会话。
- 当前原路径路由：`choose_save_target` 把「所选路径 = 当前原路径」路由为 `InPlace`，沿用普通保存的指纹、只读与冲突保护，不借目标选择绕过外部修改检测。
- 只读源另存为：`ExistingTarget`/`NewTarget` 跳过源只读校验（仅 `InPlace` 校验源只读），只读源可另存到其他可写目标。
- 系统面板由 Rust 发起、前端不提交路径、capability 未新增宽泛文件系统、shell、dialog 或网络权限。

**4. 本功能实际缺口（= 首个实现任务范围）**

可靠实现缺口收缩为 Untitled 首次保存的默认文件名（`Untitled`）与前置格式选择界面对“下一步选择路径和文件名”的可发现性。已有文档另存为的默认目录因 `rfd` macOS 保存面板渲染问题暂不作为本轮完成项；用户仍可在系统保存面板中手动切换目录与修改文件名。其余验收点已被现有实现覆盖，实现任务应避免重复改动保存核心、路由、取消与只读逻辑。

**5. 可测性**

- 后端命令直接调用 OS 对话框，无法在 CI 单测中覆盖 `blocking_save_file`；应把「给定可信状态或首次保存，决定默认文件名」提取为纯函数，使其可被确定性单测覆盖（与既有 `trusted_for_save_as`/`build_saved_descriptor` 等纯助手测试策略一致）。格式选择弹窗的目标选择说明由前端 DOM 测试覆盖；OS 面板实际可修改路径与文件名由 macOS 交互验收确认。
- OS 对话框实际传入默认值、用户可在面板修改目录与文件名，由 macOS 交互验收确认（集成验收任务）。
