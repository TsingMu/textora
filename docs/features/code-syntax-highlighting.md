# 代码文本识别与最小语法高亮

> 状态：已确认（2026-08-10）

## 背景与目标

Textora 的产品范围包含代码文本编辑，但当前已完成的能力仍主要是普通文本、多标签、保存安全、关闭保护和列块编辑。用户在 macOS 上处理来自 Windows/Unix 环境的代码、配置和脚本文件时，需要比纯文本更容易扫读结构，但首版不应把 Textora 扩展成完整 IDE。

本功能目标是建立一个轻量、可退化的代码文本显示增强：打开或保存为常见代码/配置文件后，编辑器能根据文件名或扩展名启用基础语法高亮；无法识别或高亮加载失败时，文档仍按普通文本正常编辑和保存。语法高亮只是 CodeMirror 层的派生显示，不改变文本文档作为权威源的地位。

## 范围

- 根据当前活动标签的文件显示名或路径扩展名识别常见代码/配置文本类型。
- 为首版语言清单（见下）启用 CodeMirror 基础语法高亮。
- 在状态栏显示活动文档检测到的语言（如 `Plain Text`、`TypeScript`、`JSON`），与编码·换行设置并列。
- Markdown 文件按源码高亮（标题、强调、代码块等），不引入预览。
- 新建 Untitled 或无法识别扩展名的文件继续使用普通文本模式。
- 切换标签时，高亮语言与状态栏语言随活动标签切换，不污染其他标签。
- 保存、另存为或打开不同路径后，高亮语言应跟随新的显示名/路径重新判断。
- 高亮功能失败时安全退化为普通文本编辑，不影响输入、撤销/重做、列块编辑、保存、关闭保护或编码/换行处理。

### 首版语言清单

| 语言 | 匹配输入 | CodeMirror 包（实现切片接入） |
| --- | --- | --- |
| JavaScript | `.js` `.mjs` `.cjs` `.jsx` | `@codemirror/lang-javascript` |
| TypeScript | `.ts` `.mts` `.cts` `.tsx` | `@codemirror/lang-javascript`（`typescript`/`jsx`） |
| JSON | `.json`，以及完整文件名 `package.json`、`tsconfig.json`、`jsconfig.json` 等 | `@codemirror/lang-json` |
| HTML | `.html` `.htm` | `@codemirror/lang-html` |
| CSS | `.css` | `@codemirror/lang-css` |
| Rust | `.rs` | `@codemirror/lang-rust` |
| Python | `.py` | `@codemirror/lang-python` |
| Java | `.java` | `@codemirror/lang-java` |
| Shell | `.sh` `.bash` | `@codemirror/legacy-modes`（shell StreamLanguage）或等价包 |
| SQL | `.sql` | `@codemirror/lang-sql` 或 legacy-modes |
| TOML | `.toml`，以及完整文件名 `Cargo.toml`、`pyproject.toml` 等 | `@codemirror/legacy-modes` 或等价包 |
| YAML | `.yaml` `.yml` | `@codemirror/lang-yaml` 或 legacy-modes |
| Markdown | `.md` `.markdown`（仅源码高亮，无预览） | `@codemirror/lang-markdown` |
| Plain Text | Untitled、无扩展名或未识别扩展名 | （无语言扩展） |

> 具体包选型（独立 `@codemirror/lang-*` vs `legacy-modes` 流模式）在实现切片决定；无论选哪种，未知语言都必须退化为普通文本而非报错。Shell/SQL/Python/Java 的扩展名识别在本功能首版即覆盖，即使其 CodeMirror 包分多次接入。

## 非范围

- LSP、代码补全、跳转定义、诊断、格式化、重命名或符号索引。
- 项目目录、工作区级语言识别或多文件分析。
- 语法树驱动的结构化编辑、折叠、面包屑或大纲。
- 自定义主题、语法配色偏好、按用户配置覆盖语言识别。
- 通过内容嗅探复杂判断语言；首版优先基于文件名/扩展名。
- Markdown 预览、Mermaid 预览或 Markdown 所见即所得模式（Markdown 在本功能仅源码高亮）。
- 改变文件编码、换行符、保存目标、冲突保护或 Tauri 文件权限。

## 用户流程

1. 用户打开一个已有代码或配置文件，例如 `app.tsx`、`config.json`、`Cargo.toml`、`deploy.sh`。
2. Textora 根据活动标签的文件名/扩展名选择合适的语法高亮，并在状态栏显示对应语言。
3. 用户继续像普通文本一样编辑、列块操作、撤销/重做和保存。
4. 用户切换到另一个标签时，编辑器显示该标签对应的高亮或普通文本模式，状态栏语言同步切换。
5. 用户另存为不同扩展名后，活动标签的高亮模式与状态栏语言跟随新文件名重新判断。

## 行为规则与边界情况

- 高亮只影响编辑器视觉显示，不得改写文档内容、编码、换行符或保存格式。
- 语言识别以当前活动文档的 `path` 或 `displayName` 为输入；若二者都无法提供可识别扩展名或已知文件名，则使用普通文本模式。
- 识别优先匹配完整文件名（如 `package.json`、`Cargo.toml`），再回退到扩展名；扩展名匹配大小写不敏感，例如 `.TS` 与 `.ts` 行为一致。
- 状态栏显示的语言名是识别结果的派生展示（如 `Plain Text`、`TypeScript`、`JSON`、`Markdown`），不作为保存目标或后端关联的依据。
- 切换标签、打开文件、另存为成功后，应重新计算活动标签的语言；后台标签不应因为当前标签切换而丢失自己的文档状态。
- 只读、加载、保存、另存为、冲突、文件缺失或关闭确认期间的编辑锁定规则不变。
- 高亮扩展不得破坏 CodeMirror 的多选区、矩形选择、列块删除、列块粘贴、数字序列填充和撤销/重做。
- Markdown 仅启用源码高亮，不触发预览、不解析内嵌 Mermaid，也不改变其作为普通文本文件的保存语义。
- 若某种语言包或高亮扩展无法加载，首版应退化为普通文本，而不是阻止用户查看、编辑或保存。
- 对 50 MiB 以内文件，首版不新增额外大小限制，也不对接近上限的文件静默禁用某些语言高亮：保持各语言行为一致；如某些语言高亮对大文件造成明显卡顿，作为后续性能任务处理，不在本功能内静默禁用保存或打开。

## 验收条件

- [ ] 打开或切换到已识别扩展名/文件名的文件时，编辑器启用对应基础语法高亮，状态栏显示对应语言名。
- [ ] 打开或切换到无法识别扩展名的文件时，编辑器保持普通文本模式、状态栏显示 `Plain Text`，且没有错误提示。
- [ ] 新建 Untitled 文档默认为普通文本模式，状态栏显示 `Plain Text`。
- [ ] 多标签之间高亮模式与状态栏语言相互独立，切换标签不会污染内容、脏状态、格式设置或选择状态。
- [ ] 另存为成功后，活动标签根据新的显示名/路径重新选择高亮模式与状态栏语言。
- [ ] Markdown 文件按源码高亮显示，但不引入预览或改变保存语义。
- [ ] 高亮启用后，普通输入、撤销/重做、列块删除、列块粘贴、数字序列填充仍按既有行为工作。
- [ ] 高亮功能不引入新的文件系统、shell、网络或远程页面权限。
- [ ] 自动化测试覆盖语言识别（含大小写、复合文件名、未知退化）、状态栏语言名派生、多标签切换和另存为后重新识别。
- [ ] macOS release 应用真实验收覆盖至少一种代码文件（如 `.ts`/`.py`/`.java`）、一种配置文件（如 `.json`/`.toml`/`.yaml`）、一种脚本（如 `.sh`/`.sql`）和一种未知扩展名文件。

## 实现拆分

多标签按以下顺序拆成可连续交付的小切片，实现时优先保留现有编辑/保存行为。`docs/tasks/current.md` 同一时间只保留下一个待执行切片。

1. **确认代码文本识别与最小语法高亮规格**（本任务）：确定首批语言清单、识别规则、非范围和验收方式；不修改生产代码。
2. **接入语言识别与普通文本退化契约**：新增纯函数模块（`LanguageMode` 枚举 + 按路径/显示名识别 + 语言显示名派生），覆盖大小写、未知扩展名、常见复合配置名与 Untitled 退化；不接入 CodeMirror 语言扩展、不新增依赖、不改 UI。
3. **接入 CodeMirror 基础语法高亮与状态栏语言**：新增 `@codemirror/lang-*`（及必要的 legacy-modes）依赖，把 `LanguageMode` 映射到 CodeMirror 扩展；用 `Compartment` 在活动标签、打开文件和另存为结果变化时重配置；状态栏按识别结果显示语言名。
4. **高亮与既有编辑能力回归**：验证普通输入、撤销/重做、列块编辑、多标签隔离、保存/关闭保护在高亮模式下不回退。
5. **集成验收与文档收尾**：完整自动化、release 构建和 macOS 真实应用验收；规格状态改为已完成，必要时同步 README。
